# 개발 규칙

## TDD

1. 실패하는 테스트를 먼저 작성한다.
2. 테스트를 실행해서 실패하는 것을 확인한다.
3. 테스트를 통과하는 최소한의 구현을 한다.
4. 테스트가 통과하는 것을 확인하고 정리한다.

## 테스트 이름

테스트 이름만 읽어도 그 모듈이 무엇을 하는지 알 수 있어야 한다.

- `describe`: 대상을 한국어 명사로 쓴다.
- `it`: "~하면 ~한다" 형태의 한국어 문장으로 쓴다.
- 함수명이나 내부 변수 같은 구현 세부가 아니라, 사용자나 호출자가 관찰하는 결과를 쓴다.

```ts
describe('파일 저장 형식', () => {
  it('확장자 없이 저장하면 고른 형식의 확장자를 붙인다')
  it('이미 .md로 끝나면 확장자를 덧붙이지 않는다')
})
```

## 테스트 파일 위치

`tests/` 아래에 대상 모듈과 같은 경로로 둔다.

- `src/main/files.ts` → `tests/main/files.test.ts`
- `src/renderer/fake/scenario.ts` → `tests/renderer/fake/scenario.test.ts`

## 문서

- 결정을 내리면 `DECISIONLOG.md`에 항목을 추가한다.
- 설계가 바뀌면 코드보다 설계 문서를 먼저 고친다.
- 새 문서를 만들면 `CLAUDE.md`의 문서 목록에 추가한다.

## Git

- 커밋 메시지는 한국어로, 제목과 본문만 쓴다.
- AI 관련 서명(Co-Authored-By 등)은 넣지 않는다.
